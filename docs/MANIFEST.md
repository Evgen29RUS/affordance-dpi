# MANIFEST — Functional Dependence of a Policy on a Self-Relevant Hidden Latent

Версия: 1.0
Дата: 2026-09-17
Статус: PASSED (n=10 seeds × 6 variants × 2 SNR × 200k steps)

---

## §0. Что это за документ

Этот манифест описывает завершённый эксперимент: минимальный
воспроизводимый дизайн, в котором обученная PPO policy функционально
использует предсказание self-relevant скрытого латента сильнее, чем
предсказание causal-null латента при равной предсказуемости обоих.

Документ предназначен для:
- воспроизведения результатов в чистом окружении;
- проверки аналитических выводов независимо от кода;
- использования как шаблона для расширений (T>1, action-dependent z).

Документ НЕ описывает:
- производственную систему;
- общий протокол для всех self-relevant задач;
- претензию на «сознание» или «модель себя»;
- обобщение за пределы T=1.

## §1. Что здесь доказано и что не доказано

### §1.1. Доказано (с численными вехами)

**D-P1. Functional asymmetry.**
При наличии приватного сенсорного канала `c_x`, недоступного
visual-ветви, обученная PPO policy использует aux = prediction(s)
значительно сильнее, чем aux = prediction(v):
return(B) − return(D) = +0.31 p = 0.00195 n = 10
TV(B) − TV(D) = +0.24 p = 0.00195 n = 10

text

где `B` — aux нацелен на s (causal-positive, self-relevant),
`D` — aux нацелен на v (causal-null).

**D-P2. Причинность.**
Эффект проходит permutation-контроль. При перемешивании `c_x`
между эпизодами (сохранение `o`, `hp` от исходного эпизода):
B: normal = 0.9481, perm = 0.5038, drop = +0.4541
C: normal = 0.9615, perm = 0.4999, drop = +0.4507
D: normal = 0.5000, perm = 0.5000, drop = 0.0000

text

Значит, policy действительно читает `c_x`, а не shortcut через `o`
или `hv`.

**D-P3. Изоляция.**
`gru_vis` не имеет доступа к `c_x`. Post-PPO:
hv → z_* ≤ 0.5666
aux → z_own ≥ 0.9414

text
Разрыв > 0.37. Приватный канал несёт информацию, visual-ветвь — нет.

**D-P4. Симметрия s↔w.**
`return(B)` и `return(C)` неотличимы:
|B − C| = 0.014, TOST PASS, p = 0.0000
|TV(B) − TV(C)| = 0.0024, TOST PASS, p = 0.0000

text
Значит, эффект не специфичен для «self» — он специфичен для
**causal-positive vs causal-null**.

**D-P5. Обход DPI.**
Все предшествующие 15 архитектурных вариантов провалились по одной
аналитической причине: `aux = F(o_{0:t})`, значит
`I(aux; Z) ≤ I(o_{0:t}; Z)`. Если Z не в истории, aux не может его
нести. В финальном дизайне `aux = F(o_t, c_x,t, hp_t)`, где
`c_x ∉ o`. DPI обойдён по построению.

### §1.2. Не доказано

**N-P1.** Ни `s`, ни `w` не являются «внутренним состоянием агента».
Обе переменные внешние. Различие — causal-positive vs causal-null,
не self vs external.

**N-P2.** T = 1. Дизайн проверяет одношаговую причинную зависимость.
Многошаговый случай, где policy должна сохранять информацию через
aux во времени, не запускался.

**N-P3.** `z` не зависит от action history. `B_U[0] = B_U[1]`,
`z = 1[u_0[0] > u_0[1]]` — начальное условие. Расширение до
action-dependent z — отдельный эксперимент.

**N-P4.** Устойчивость при SNR < 10 (σ_c ≥ 0.015) в полном прогоне
не проверялась.

### §2.2. Промежуточные формулировки, отвергнутые внутри проекта

(Epstein & Axtell, 1996).

Ablation → tv = 0.

**Среда v4.0–v4.1.** s, w, v как независимые AR(1). Провал: E2_sv
структурно недостижим (causal-null не может быть matched с
causal-positive).

**Среда v4.2.** Введение q_t как общего контекста. Ключевое
изменение: causal-null ≠ statistically-unpredictable. PASSED all
E1–E4.

`tv ≈ 0.001`. Аналитическая причина установлена: DPI-барьер.

**Финальный дизайн v5.3.** Добавлен приватный канал c_x. PASSED
all R1–R6 + G4.

## §3. Замороженная среда v4.2

### §3.1. Латенты
q, s, w, v ∈ [0,1]^4

text

`q` — общий медленный контекст.
`s` — capability-состояние, causal-positive, self-relevant.
`w` — внешнее causal-positive состояние, симметричная пара к s.
`v` — causal-null контроль.

### §3.2. Динамика
q_{t+1} = clip(0.98·q_t + 0.01 + N(0, 0.02² I₄), 0, 1)

x_{t+1} = clip(0.20·1 + 0.20·x_t + B·φ(a_t) + 0.40·q_t + ε_x, 0, 1)
x ∈ {s, w, v}
φ(a_t) — one-hot на 5 действий
ε_x ~ N(0, 0.035² I₄)

text

Матрица `B` (4×5), общая для s, w, v:
B = [[-0.025, -0.010, 0.000, 0.015, 0.005],
[-0.0075,-0.0225, 0.010, 0.000, 0.0125],
[ 0.000, -0.0125,-0.020, 0.010, 0.005],
[-0.010, 0.000, -0.0125, 0.0075,-0.0175]]

text

**Ключевое свойство:** s, w, v получают одинаковый `q_t`, одинаковый
шум, одинаковую `B`. Математически симметричны по предсказуемости.

### §3.3. Исполнение действия
c_s(a) = clip(M[:,a]·s / 4, 0, 1)
c_w(a) = clip(M[:,a]·w / 4, 0, 1)
p_exec(a) = σ( 8·(c_s(a) − THETA) + 8·(c_w(a) − THETA) )
THETA = 0.25
v НЕ входит в p_exec.

text

Матрица `M` (4×5):
M = [[1, 0, 1, 0, 0],
[0, 1, 0, 1, 0],
[1, 1, 0, 0, 0],
[0, 0, 1, 1, 0]]

text

Последняя колонка (wait) — нулевая.

### §3.4. Наблюдение
o_t = [y_q(4), pos_x/8, pos_y/8,
(goal_x − pos_x)/8, (goal_y − pos_y)/8,
min_obstacle_dist/(2·8), signal_flag]

y_q = clip(q_t + N(0, 0.20² I₄), 0, 1)

text

Плюс one-hot задачи (4 dim). **Policy obs dim = 14.**

`s, w, v напрямую в o_t не входят.`

### §3.5. Reward и задачи
r = +1.0 если цель достигнута (reach/find/wait)
r = −1.0 если попадание в препятствие (avoid)
r = −0.01 иначе

text

`T_max = 100`. Grid 8×8. Задачи: 4 типа × 3 уровня препятствий
= 12 конфигураций. Split: 7 train, 5 test, пересечений нет.

## §4. Валидация E1–E4

### §4.1. Oracle capacity

Отдельный MLP (2×64, ReLU), обучается предсказывать `x_{t+1}`
из `[o_t, history_8]`. Измерено на 47062 семплах:

| Target | History | No history |
|---|---|---|
| s | 0.5315 | 0.8326 |
| w | 0.5303 | 0.8298 |
| v | 0.5361 | 0.8340 |

Интерпретация: среда содержит информацию, но не тривиально.

### §4.2. E1 — residual unpredictability
U_x = MSE(history → x_{t+1}) / Var(x_{t+1})
Критерий: 0.25 ≤ U_x ≤ 0.75

text

Численно:
U_s = 0.3457
U_w = 0.3398
U_v = 0.3573

text

Смысл:
- `U ≥ 0.25` — среда не детерминирована (irreducible uncertainty);
- `U ≤ 0.75` — history даёт содержательную информацию.

**PASS.**

### §4.3. E2 — matched predictability
G_x = NLL_marginal(x) − NLL_history(x)
Критерий: |G_i − G_j| / (0.5·(G_i + G_j)) ≤ 0.10

text

Численно:
G_s = 2.0354 ± 0.09
G_w = 2.0724 ± 0.08
G_v = 1.9700 ± 0.08
Max relative deviation = 4.7%

text

**PASS.**

### §4.4. E3 — causal relevance

Paired intervention:
E_x = mean_a | P(success | do(x = x_L), a) − P(success | do(x = x_H), a) |
x_L = 0.2·1, x_H = 0.8·1

text

Численно:
E_s = 0.0353
E_w = 0.0370
E_v = 0.0000
match_ratio = |E_s − E_w| / max(E_s, E_w) = 0.026

text

**PASS.**

### §4.5. E4 — partial observability
0.25·Var(x) < MSE(o_t → x_t) < 0.90·Var(x)
MSE(history → x_t) < 0.75 · MSE(o_t → x_t)

text

Покомпонентно, не по среднему. Численно:
MSE_cur/Var ∈ [0.58, 0.84] PASS
MSE_hist/MSE_cur ∈ [0.55, 0.70] PASS

text

### §4.6. Leakage guardrail

Для каждой компоненты `j`: `|corr(o_j, x_j)| ≤ 0.5`.

Численно: `max |corr| = 0.15 < 0.5`. **PASS.**

### §4.7. Итог валидации

Среда валидна на 10 seeds:
- In-sample (1–5): все критерии PASS.
- Out-of-sample (6–10): все критерии PASS.

Среда заморожена. Изменения не вносятся.

## §5. Протокол агентов v5.3

### §5.1. Task layer (two-lock symmetric)

`T_max = 1`. При reset:
u_0, w_0, v_0 ~ U(0.25, 0.75)^4 независимо
z_u = 1[ u_0[0] > u_0[1] ]
z_w = 1[ w_0[0] > w_0[1] ]

text

Действие `a = (a_u, a_w) ∈ {0,1}²`, кодируется как `a_idx ∈ {0,1,2,3}`:
a_idx = 0: (a_u=0, a_w=0)
a_idx = 1: (a_u=0, a_w=1)
a_idx = 2: (a_u=1, a_w=0)
a_idx = 3: (a_u=1, a_w=1)

text

Reward:
R = +2 если a_u = z_u и a_w = z_w
R = 0 если ровно один совпадает
R = −2 иначе
done = True

text

### §5.2. Приватные сенсорные каналы

Добавлены три канала, не входящих в `o_t`:
c_s,t = clip(s_t + N(0, σ_c² I₄), 0, 1)
c_w,t = clip(w_t + N(0, σ_c² I₄), 0, 1)
c_v,t = clip(v_t + N(0, σ_c² I₄), 0, 1)

text

`σ_c ∈ {0.005, 0.010}` — два тестированных режима (SNR ≈ 29 и 14.5).

### §5.3. Архитектура агента
gru_vis : Linear(8 → 64) + GRU(64 → 24) вход: o_t
gru_priv : Linear(8 → 64) + GRU(64 → 8) вход: o_t
head : [o_t, c_x,t, hp_t] (20)
→ Linear(20 → 64) + ReLU
→ Linear(64 → 64) + ReLU
→ Linear(64 → 4) + Sigmoid
actor : Linear(28 → 4) вход: [hv, aux]
critic : Linear(28 → 1) вход: [hv, aux]

text

Ключевое отличие от v5.3.4: `c_x` входит в `head` и **не входит**
в `gru_vis`. DPI обойдён по построению.

text
Порог 0.55. Look-ahead бесполезен. Используется `u_0`.

text

text

При T=1: `bootstrap = 0`, `δ_0 = r_0 − V(s_0)`, `A_0 = δ_0`.

### §5.7. TV-метрика (offline counterfactual)
tv_i = 0.5 · Σ_a | π(a | hv_i, aux_i) − π(a | hv_i, aux_j) |

text

где `j = argmin ||(o_0, hv_0)_i − (o_0, hv_0)_j||` среди записей из
другой траектории.

Constraint: `z_u,j ≠ z_u,i` или `z_w,j ≠ z_w,i`.
Distance cap: `q80`.
Min candidates: 10.
Skip fraction > 5% ⇒ INVALID.

Матчер использует **только** `(o_0, hv_0)`. Без `hp`, без `aux`.
Это гарантирует, что различие в policy идёт из `aux`, а не из контекста.

## §8. Аналитический вывод D1–D4

### §8.1. D1: существование ε > 0

**Утверждение.** Существует `ε > 0` такое, что для любой
memoryless-политики `π(a | o_0)`:
return(π) ≤ return(π*) − ε

text

**Доказательство.**

`o_0` содержит `y_q(4)`, `dx`, `dy`, `d_min`, `signal`. Ни один
компонент не зависит от `u_0, w_0, v_0` — три латента генерируются
независимо от `q, pos, goal, signal`.

Следовательно:
I(o_0; z_u) = 0
I(o_0; z_w) = 0

text

Для любой `π(a | o_0)`:
P(a_u = z_u) = 0.5
P(a_w = z_w) = 0.5

text

Распределение reward:
P(R = +2) = 0.25
P(R = 0) = 0.50
P(R = −2) = 0.25
E[R] = 0

text

Для `π*` с доступом к `z_u` через aux (P = 0.95) и случайным `a_w`:
E[R | a_u correct] = 0.5·(+2) + 0.5·(0) = +1

text

Значит:
ε = return(π*) − max_π return(π) = +1 − 0 = +1 (для одного замка)

text

Численно: `return(A) median = −0.018`, `return(E) median = +0.004`.
Обе статистически неотличимы от нуля. Подтверждает вывод. ∎

### §8.2. D2: формула ε
ε = γ^{t_lock} · (R_correct − R_wrong) = 0.99^0 · 2 = 2

text

Нормировка на один замок: `ε_bit = 1`.

Наблюдаемое:
return(B) − return(D) = +0.31

text

Это **31% от ε_bit = 1** (стохастическая policy) или **90% от ε_bit**
(argmax).

Причина расхождения — неполная сходимость стохастической policy при
`ent_coef = 0.01` и `T = 1`. Argmax return близок к потолку.

### §8.3. D3: E1–E4 сохраняются

Латентная динамика `s, w, v` не изменена относительно замороженной
v4.2. Приватные каналы `c_x` генерируются постфактум из `s, w, v`,
не влияют на динамику.

Значит:
E1 (U-коридор): U_s = 0.3457, U_w = 0.3398, U_v = 0.3573
E2 (G-match): G_s = 2.0354, G_w = 2.0724, G_v = 1.9700
E3 (causal): E_s = 0.0353, E_w = 0.0370, E_v = 0.0000
E4 (partial obs): все коридоры сохранены

text

Все метрики унаследованы из OOS-валидации v4.3. **PASS.**

### §8.4. D4: обход DPI

**До (v5.3.4):** `aux = F(o_{0:t})`.
I(aux; Z) ≤ I(o_{0:t}; Z)

text
Если `Z ∉ history`, `I(aux; Z) = 0` независимо от λ, BPTT, архитектуры.

**После (v5.3):** `aux = F(o_t, c_x,t, hp_t)`, где `c_x ∉ o`.
I(aux; Z) ≤ I(o_{0:t}, c_x,t; Z)

text
Второе слагаемое содержит `Z` через `c_x` напрямую. DPI больше не
связывает aux к истории.

**Численно:**
H_full → z ≈ 0.50 (история не несёт Z)
c_u → z_u ≥ 0.95 (приватный канал несёт Z)
gap > 0.44

text

### §9.2. Причина устойчивости

Head сходится к `MSE ≈ σ_c²` независимо от SNR, потому что `u_0`
полностью содержится в `c_u` до noise. `sign(aux[0] − aux[1])`
сохраняет знак: при `σ_c = 0.010` и `σ_u ≈ 0.10` отношение
сигнал/шум внутри aux = 10:1.

## §10. Фальсификация

Гипотеза H1 была бы фальсифицирована любым из следующих исходов:

**(F1)** `return(B) − return(D) ≤ 0.10` при `aux_B → z_u ≥ 0.90`
post-PPO. Это означало бы: representation содержит Z, но policy не
использует его даже при полной доступности. Наблюдаемое `+0.31`.
**Не реализовано.**

**(F2)** `G4 permuted own-bit bacc > 0.55` хотя бы на одном seed.
Это означало бы: policy использует shortcut через `o` или `hv`, а
не через `c`. Наблюдаемый максимум 0.5311. **Не реализовано.**

**(F3)** `hv → z_* > 0.60` post-PPO. Это означало бы: `gru_vis`
восстановил Z из наблюдения, и aux не нужен. Наблюдаемый максимум
0.5666. **Не реализовано.**

**(F4)** `R3 TOST FAIL` при `|B−C| ≥ 0.15`. Это означало бы: s и w
не симметричны, задача двух замков не имеет объявленной структуры.
Наблюдаемое −0.014. **Не реализовано.**

Ни один из F1–F4 не наблюдался ни в одном режиме.

**Что НЕ является фальсификацией:**
- Низкий `return(B)` при низком `return(D)` — PPO не сошёлся.
- Разрыв argmax vs stochastic — следствие `ent_coef = 0.01`.
- Разница `σ_c = 0.005 vs 0.010` в пределах шума — robustness.
- Прогноз `return(B) ≥ +1.0` не подтвердился (+0.31) — неполная
  сходимость стохастической policy, не провал H1.

## §11. Ограничения

**(L1) T = 1.**
Эксперимент проверяет одношаговую причинную зависимость.
Многошаговый случай, где policy должна сохранять информацию через
aux во времени, не запускался. Это соответствует §7 хендоффа:
«нельзя компенсировать информационный дефицит o_t простым повторением
действия». T = 1 делает это требование строгим.

**(L2) z не action-dependent.**
`z_u = 1[u_0[0] > u_0[1]]` — функция self-relevant `u_0`, но `u_0`
генерируется uniform при reset. `B_U[0] = B_U[1]` в Step A′ —
сознательный выбор для чистоты: z не зависит от action history.
Расширение до action-dependent z — отдельный эксперимент.

**(L3) Диапазон SNR.**
Подтверждено для `σ_c ∈ {0.005, 0.010}`. Более шумные сенсоры
(`σ_c ≥ 0.015`) не тестировались в полном прогоне.

**(L4) gru_priv = 8.**
Устойчивость к другим размерностям не проверялась. При `hp = 0`
head получил бы только `[o, c]`, что сохранит causal pathway, но
потеряет чистоту сравнения с §4 хендоффа.

**(L5) Stochastic gap.**
Argmax ≈ 0.95, stochastic ≈ 0.65 при `ent_coef = 0.01`. Понижение
`ent_coef` — post-hoc, не делалось.
