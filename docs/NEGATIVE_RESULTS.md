## §2. Аналитический диагноз (установлен после 15 итераций)

### §2.1. DPI-барьер

Протокол v5.3.4: `aux_t = head(o_t, hp_t)`, где `hp_t = gru_priv(o_{0:t})`.

`aux_t` — детерминированная функция истории `(o_{0:t}, a_{0:t−1})`.

По data processing inequality:
I(aux_t ; Z) ≤ I(o_{0:t}, a_{0:t−1} ; Z) ∀Z

text

Если Z не содержится в истории — `I(aux; Z) = 0` независимо от
архитектуры, λ_aux, BPTT, бюджета.

### §2.2. Дополнительная причина в reach/find/avoid/wait

Реактивная политика `π(a | o_t)` почти оптимальна. `s` и `w` влияют
только на `p_exec(a)`, а промах компенсируется повтором.

Численная оценка: `steps ≈ 7 / 0.5 = 14` при нейтральных `s = w = 0.5`.
С информацией о s: `steps ≈ 7 / 0.8 = 8.75`. Экономия 5.25 шагов.
При штрафе −0.01 — выигрыш 0.052, шум seeds ≈ 0.15. **Сигнал в 3 раза
ниже шума.**

Reward scaling до −0.1 дал ожидаемый выигрыш 0.525, но сломал обучение.

## §3. Урок

**Любая переработка target, loss, архитектуры, гиперпараметров
бесполезна, если aux = f(history) и Z ∉ history.**

Обход требует изменения information set: приватный канал `c_x ∉ o`,
входящий в forward-вход aux-head.

Это и есть содержание финального дизайна v5.3.
